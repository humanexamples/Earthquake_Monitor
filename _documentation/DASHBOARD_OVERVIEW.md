# Earthquake Monitor — Dashboard Overview

The Streamlit dashboard at `localhost:8501` is organized into five pages, each backed by a different table in the Gold layer Data Warehouse.

---

## 1. World Map (`gold.earthquake_events`)

An interactive global map powered by **Pydeck/Deck.gl** showing every processed earthquake as a circle. The circle's **size and color encode the composite impact score** — green for low, yellow for moderate, red for high. Three sliders let you filter by:
- Last N days (1–90)
- Minimum magnitude
- Minimum composite score

Hovering a marker shows a tooltip with region, magnitude, depth, and all four sub-scores (tsunami risk, building vulnerability, population exposure, infrastructure risk). Below the map sits a **Top 10 highest-impact events** table.

### 1.1 The composite score

The `composite_score` is a **weighted average of four sub-scores**, all on a 0–10 scale, calculated in [services/spark-jobs/impact_scoring.py](vscode-webview://0hs34rpns60nkimdq53kub5hrqrjkl10cf9ne2p6atdd3hhqu54l/services/spark-jobs/impact_scoring.py) as a Spark job on the Silver layer data (All four are clamped to `[0, 10]`):

| Score                      | Formula                                   | What it captures                                             |
| -------------------------- | ----------------------------------------- | ------------------------------------------------------------ |
| **Tsunami Risk**           | `(magnitude - 4) × 2.5 × (1 - depth/300)` | Shallow, high-magnitude quakes near the surface are most dangerous for tsunamis |
| **Building Vulnerability** | `1.5 × magnitude - 0.0133 × depth + 1.3`  | Approximates MMI (Modified Mercalli Intensity) — shallower and stronger = more structural damage |
| **Population Exposure**    | `population_50km / 1,000,000`             | People within 50 km of the epicenter (currently a placeholder — data not yet enriched, so always 0) |
| **Infrastructure Risk**    | `magnitude × 0.8 + (1 - depth/300) × 2`   | Combined effect of magnitude and shallow depth on infrastructure |

```
composite_score = tsunami_risk      × 0.30
               + building_vuln      × 0.25
               + population_exposure × 0.25
               + infrastructure_risk × 0.20
```

**The composite formula**: **Tsunami risk** is given the highest weight (30%) because it has the broadest destructive reach. Building vulnerability and population exposure share 25% each, and infrastructure risk gets 20%.

#### 1.1.1 Where the raw data comes from

**EMSC (European Mediterranean Seismological Centre)** is the single source of the seismic measurements. The [emsc_listener.py](vscode-webview://0hs34rpns60nkimdq53kub5hrqrjkl10cf9ne2p6atdd3hhqu54l/services/emsc-listener/emsc_listener.py) maintains a persistent WebSocket connection to EMSC and streams every event into Kafka. Each event carries:

- `mag` → magnitude
- `depth` → depth in km
- `lat`, `lon` → epicenter coordinates

**1. Tsunami Risk (Only uses: `magnitude` + `depth`)**

**Tsunami Risk** is based on the well-known empirical observation that tsunamis are generated by shallow, high-magnitude submarine earthquakes. The threshold of M4.0 as a minimum and the depth attenuation factor `(1 - depth/300)` reflect NOAA/PTWC (Pacific Tsunami Warning Center) guidance that quakes deeper than ~300 km rarely generate tsunamis. The linear scaling is a simplification of that principle. [Reference](https://www.noaa.gov/jetstream/tsunamis/tsunami-generation-earthquakes)

```
(magnitude - 4) × 2.5 × (1 - depth / 300)
```

- Quakes below M4 score 0.
- A shallow quake (depth → 0) gets the full multiplier of 1.
- A deep quake (depth → 300 km) gets multiplier → 0, because deep quakes rarely generate tsunamis.

### 2. Building Vulnerability (Only uses: `magnitude` + `depth`)

*“Intensity Prediction Equations for North America.”*   *Bulletin of the Seismological Society of America*, 97(2), 550–570.

```
1.5 × magnitude − 0.0133 × depth + 1.3
```

This approximates the **Modified Mercalli Intensity (MMI)** — how strongly the ground shakes at the surface. Higher magnitude and shallower depth = more shaking = more structural damage.

### 3. Population Exposure (It uses WorldPop API data)

The [enrichment_job.py](vscode-webview://0hs34rpns60nkimdq53kub5hrqrjkl10cf9ne2p6atdd3hhqu54l/services/flink-enrichment/enrichment_job.py) calls the **WorldPop API** to get population density within 50 km of the epicenter. However, in [impact_scoring.py](vscode-webview://0hs34rpns60nkimdq53kub5hrqrjkl10cf9ne2p6atdd3hhqu54l/services/spark-jobs/impact_scoring.py#L66) the field is set as a placeholder:

```python
F.lit(None).cast(DoubleType()).alias("population_50km")  # population_data not enriched
```

So `population_exposure` is **always 0** right now — the WorldPop data is fetched and stored in the Silver layer but not yet wired into the scoring job.

### 4. Infrastructure Risk

**Only uses: `magnitude` + `depth`**

```
magnitude × 0.8 + (1 − depth / 300) × 2
```

Combines raw energy (magnitude) with shallow-depth amplification, reflecting damage to roads, bridges, and utilities.

## Summary

| Score                  | Intended data source        | Actually used                   |
| ---------------------- | --------------------------- | ------------------------------- |
| Tsunami Risk           | EMSC (mag, depth)           | Yes                             |
| Building Vulnerability | EMSC (mag, depth)           | Yes                             |
| Population Exposure    | WorldPop API (50 km radius) | **No — always 0 (placeholder)** |
| Infrastructure Risk    | EMSC (mag, depth)           | Yes                             |

The enrichment job fetches four external APIs (USGS, WorldPop, Overpass/OSM, Open-Meteo), but **impact_scoring.py currently only uses EMSC's magnitude and depth**. The richer enrichment data sits in the Silver layer waiting to be wired in.

---

## 2. Event Table (`gold.earthquake_events`)

A fully **filterable and sortable table** of all scored events from the Gold layer. Sidebar controls let you narrow by region (dropdown from live data), magnitude range, minimum composite score, and date window. The header shows four summary metrics: total events, max magnitude, max composite score, and average composite score. The table renders `composite_score` and `tsunami_risk` as **progress bars**. A **Download as CSV** button exports the filtered result.

---

## 3. Regional Stats (`gold.regional_stats`, `gold.daily_summary`)

Three aggregated visualizations comparing regions:

- **Horizontal bar chart** — top 20 regions ranked by average composite score, color-scaled red-to-green.
- **Scatter plot** — max magnitude vs. max composite score, where bubble size = total event count and color = average tsunami risk. Good for spotting which regions combine high magnitude *and* high impact.
- **Global daily trend** — a dual-axis combo chart (bar for event count + line for max magnitude) for the last 30 days, pulling from `gold.daily_summary`.

A collapsible expander at the bottom shows the raw regional data table.

---

## 4. Monitoring Window (`gold.earthquake_events` + `monitoring.events`)

Focused on **high-danger events: M≥6.0, depth < 150 km, within the last 7 days**. For each such event you can select from a dropdown and see:

- Key metrics: magnitude, depth, composite score, tsunami risk.
- **GDACS alert level** (Red / Orange / Green) from the last poll.
- **NOAA warning** timestamp.
- **USGS aftershock count over time** as a line chart — updated every 15 minutes by an Airflow DAG.
- **Open-Meteo weather forecast** (temperature, precipitation, wind) for the epicenter location.

The page ends with a summary table of all currently monitored events.

---

## 5. Data Quality (`gold.quality_profiles`)

A daily health check of the entire **Medallion pipeline (Bronze → Silver → Gold)**. It shows:

- **Latest snapshot per layer**: row count, distinct IDs, and duplicate count (green dot if zero, red dot if any).
- **Row count trend** as a multi-line chart over time — lets you spot drops in data volume.
- **Duplicate count bar chart** grouped by layer and day.
- **Gold layer daily stats** table: event count, max and avg composite score per processing date.

Data is populated by the `data_quality_report` Airflow DAG, which runs daily at midnight. A collapsible expander shows the raw profile records.
